# Level‑2：分块模型（create/join/post/wait/mutex）与实现计划（2026-02-05）

目标：在不破坏现有 Level‑1（create/join）能力的前提下，引入 Level‑2 分块规则，把 `sem_post/sem_wait` 与 `pthread_mutex_lock/unlock` 的信息纳入一个“可用于调度/插桩/实验”的段级模型，并最终生成我们想要的 DAG（含多入边）。

本文只定模型与工作计划；实现按步骤推进与验收。

---

## 1. 背景与共识

### 1.1 为什么需要 Level‑2

- Level‑1/Stage‑1 目前只切 `pthread_create/join`，得到的更像“线程生命周期骨架图”，无法表达学术 benchmark DAG 常见的 fan‑in（多入边）。
- 我们已在基准程序中引入 `sem_post/sem_wait`（统一写法、一行一句），用同步依赖来表达真实 precedence 关系。
- 同时引入 `mutex` 的目的是：识别并单独成段“临界区段”，用于结构理解与后续统计（当前阶段**不把 mutex 转成依赖边**）。

### 1.2 当前阶段已确认的约束（来自讨论）

- `sem_post/sem_wait`：保证统一写法 `sem_wait(&semX)` / `sem_post(&semY)`，便于配对与建边。
- `mutex`：当前阶段只做“临界区段（lock→unlock）”，不引入资源约束边参与调度。
- 结构粒度 vs 研究粒度：两套粒度同时支持
  - 结构粒度：更细，便于理解 DAG 结构（也便于验证 post/wait 配对）
  - 研究粒度：更粗，便于调度算法（LPF/后续算法）与优先级插桩

## 2. Level‑2 分块模型（建议定义）

### 2.1 基本对象

- **Segment（段）**：源码中的连续行区间 `[start_line, end_line]`，属于某个函数（线程入口函数或 main）。
- **Edge（边）**：段之间的依赖关系，分类型，用于构造段级 DAG。

### 2.2 段类型（结构粒度）

在结构粒度下，段类型建议最少包含：
1) `compute`：普通计算段（含 busy_wait/普通语句）
2) `sync_sem_wait`：`sem_wait(&S)` 单行段（阻塞点）
3) `sync_sem_post`：`sem_post(&S)` 单行段（释放点）
4) `sync_mutex_cs`：临界区段（从 lock 到 unlock 的代码区间，见 2.4）

> 本阶段决定：`pthread_create/join` **不必单独成段**（与你的最新思路一致）。
> 它们仍然可以被 Level‑1 的结构图展示（用于骨架理解），但 Level‑2 的“研究粒度 DAG”不强依赖 create/join 作为切段点。

### 2.3 边类型（结构粒度）

边建议至少包含两类：

1) `intra`：同一函数内段的顺序边（按行号自然连接）
2) `sem_dep`：由 `sem_post -> sem_wait` 推导的依赖边（跨线程/跨函数）

> mutex 目前不转边；仅作为“段类型/统计对象”存在。

### 2.4 临界区段（mutex）规则（当前最小可落地版本）

段定义：识别同一函数内的 `pthread_mutex_lock(&m)` 与后续匹配的 `pthread_mutex_unlock(&m)`，并生成一个 `sync_mutex_cs` 段覆盖它们之间（建议先包含 lock/unlock 行，便于可视化）。

最小版本限制（先保证稳定性）：
- 仅处理“同一函数内、非嵌套”的 lock/unlock 配对
- 遇到嵌套/跨函数：记录 warning，跳过或退化为 compute 段

## 3. 两种粒度输出（同一份源码，两套视图）

### 3.1 结构粒度（用于验证与理解）

- 输出 `segments_level2_struct.json`：包含 `compute/sem_wait/sem_post/mutex_cs`
- 输出 `dag_level2_struct.json`：包含 `intra + sem_dep` 边
- 用途：
  - 直观看到 post/wait 的依赖线是否正确补齐（多入边是否出现）
  - 直观看到 mutex 临界区段是否被正确识别

### 3.2 研究粒度（用于调度与优先级插桩）

折叠策略（建议）：
- `sem_wait/sem_post`：合并进相邻 compute 段（例如“wait 属于后继段的前缀”，“post 属于前驱段的后缀”），从而减少节点数并让段权重更贴近“任务执行块”。
- `mutex_cs`：保持单独成段（你已明确“mutex 包裹住的代码段需要单独成块”）。
- 输出 `segments_level2_sched.json` / `dag_level2_sched.json`

用途：
- 段级测时 → 权重 → 优先级计算 → 插桩对照实验

> 折叠只改变“段的边界与段集合”，不改变 `sem_dep` 的拓扑语义。

## 5. Level‑2 信息文件（中间层：把识别结果固定下来）

为把“可视化工具的解析结果”变成“可用于分段/建边/插桩”的稳定输入，建议新增一个中间信息文件：

文件名建议：`mycallyplus_v1/中间结果/<base>/level2/level2_sync_info.json`

字段建议（最小集）：
- `source_file`：源文件路径
- `semaphores[]`：每条记录包含
  - `idx`（来自 circle.txt）
  - `var`（sem 变量名）
  - `post` / `wait` 的节点名（dot 节点名或函数/调用点 key）
  - `post_line/post_file`、`wait_line/wait_file`（若可得）
- `mutexes[]`：每条记录包含
  - `idx`、`var`（mutex 变量名）
  - `lock_node/unlock_node`
  - `lock_line/lock_file`、`unlock_line/unlock_file`

> 这个文件的作用是：把“配对结果”与“定位信息”固定住，避免每次都从 UI 逻辑/文本解析重算。

## 6. 从信息文件构建 Level‑2 段级 DAG（核心实现点）

构建流程建议分 3 步：

1) **扫描源码**（基于行号范围 + Level‑1 的函数范围解析）生成初始 `compute` 段
2) **应用同步切点**：
   - 在对应行号处切出 `sem_wait/sem_post` 单行段
   - 按 lock/unlock 行号对生成 `mutex_cs` 段（并与 compute 段做切分/覆盖处理）
3) **建边**：
   - intra：同一函数内按段序连接
   - sem_dep：对每个配对 `post -> wait`，将“post 所在段”连到“wait 所在段”

折叠输出（研究粒度）作为后处理：在 `segments_level2_struct` 基础上按规则合并边界，重写段集合与 intra 边。

## 7. 实施计划（分步骤、每步有验收）

### Step 0：准备验收样例
- 使用 `zhang1` 或其它包含 `sem_*` 与 `mutex_*` 的基准程序作为验证输入。
- 产物：能生成 `circle.txt`，且 GUI 的信号量/互斥锁功能能看到配对结果。

验收：GUI 中“生成信号量图/查看互斥锁”均能显示有效结果。

### Step 1：抽取并落盘 Level‑2 信息文件（只做收集，不改分段）
- 实现一个脚本/模块：读取 `circle.txt` → 输出 `level2_sync_info.json`
- 复用 UI 中已有解析逻辑（或抽到公共模块），避免重复造轮子

验收：`level2_sync_info.json` 里的 post/wait 与 mutex lock/unlock 对数与 GUI 显示一致。

### Step 2：实现结构粒度 Level‑2 分块 + 段级 DAG
- 输入：Level‑1 的 `functions_ranges.json`（函数范围） + `level2_sync_info.json`
- 输出：`segments_level2_struct.json` + `dag_level2_struct.json` + dot/png

验收：结构粒度 DAG 中出现预期的 fan‑in 边；mutex 临界区段数量与配对一致。

### Step 3：实现研究粒度折叠视图（用于调度/插桩）
- 输入：结构粒度 segments/dag
- 输出：`segments_level2_sched.json` + `dag_level2_sched.json`

验收：节点数减少且边拓扑保持一致（sem_dep 不丢）。

### Step 4：把 Level‑2 接入测时/优先级/插桩流水线
- 段级测时：针对研究粒度段插桩（compute + mutex_cs；sem_wait/post 是否计时由后续讨论决定）
- 优先级计算：沿用最长路径 criticality（或你指定的新算法）
- 优先级插桩：在研究粒度段起点插入优先级切换（具体作用对象后续讨论）
- 对照实验：baseline/prio，统一 PROGRAM_TOTAL_NS 口径

验收：能自动产出 baseline/prio 对照实验并稳定跑通；结果归档格式与现有一致。
