# 关键路径型任务：权值（负载）修改方法

本文档用于指导如何**只通过修改源文件中的计算权值（如 `#define Cx ...`）**，把一个已完成分块建模的任务调整成“关键路径优先型”（使 LPF/CPF/HEFT/Zhao2020 等关键路径/关键度策略更容易获益，而 FIFO 更容易吃亏）。

## 1. 先看“段级 DAG”

以 `zhang2` 为例，段级 DAG 位于：

- `中间结果/zhang2/pipeline/blocks/level2/effective_line_merge/dag_seg.dot`
- `中间结果/zhang2/pipeline/blocks/level2/effective_line_merge/dag_seg.json`
- `中间结果/zhang2/pipeline/blocks/level2/effective_line_merge/segments.json`

常见边类型含义：

- `create`：线程创建依赖（父线程创建子线程）
- `join`：回收依赖（`pthread_join` 等待子线程结束）
- `sem_dep`：信号量 post/wait 依赖（跨线程同步）
- `intra`：同一函数/线程内的顺序边

**关键路径“偏向 create/join”** 的目标，是让 makespan 更主要由 `create -> (子线程计算) -> join` 这条链决定，而不是被大量 `sem_dep` 或主线程串行段锁死。

## 2. 把“段节点”映射回“权值宏”

分块的段节点形如：

- `MU:worker_c2#003@105-108`
- `MU:main#004@184-187`

其中 `@105-108` 是源文件行号范围。做法：

1) 打开 `segments.json`，找到该 `seg_id` 对应的 `start_line/end_line`。
2) 在源文件里定位到这些行号附近，确认该段中对应的计算点（通常是 `busy_wait_seconds(Cx)` 或其他可调负载）。
3) 记录“段节点 -> 宏（Cx）”的对应关系。

备注：同一个宏（如 `C10`）如果在主线程多处重复使用，会同时影响多个段的权重；这种情况下更要避免把它调得过大，否则会造成“主线程串行瓶颈”，任何调度算法都很难改善。

## 3. 权值设计的通用策略

### 3.1 让关键路径算法更容易赢

- **把 `create` 链上的子线程入口段做重**：例如 `main#001 -> worker_*#001` 这些入口段所包含的 `Cx`。
- **把被 `join` 等待的子线程尾部段做重**：让 `join` 真正“等的是子线程计算”。
- **把 `sem_dep` 相关段适当做轻**：避免关键路径被 `sem_dep` 同步链吞没（除非你希望关键路径就是同步链）。
- **压低主线程重复出现的串行计算段**（典型：主线程里重复调用同一个 `Cx`）：否则关键路径会退化成“主线程串行”。

### 3.2 让 FIFO 更容易吃亏

核心思路是：在一段时间窗口内让 ready 集合 > 核数，并且让“非关键但很重”的段先就绪、易被 FIFO 先拿到 CPU，从而推迟关键段启动。

不过在很多实验代码里（例如主线程先 `pthread_create` 再推进同步/回收），更常用的做法是直接把关键链做得足够重、并减少主线程瓶颈，让关键路径类策略的优先级注入能更明显地保护关键段。

## 4. 以 zhang2 为例（create/join 关键路径）

`zhang2` 的 DAG 里：

- `create`：`MU:main#001@139-175 -> MU:worker_c0#001@132-134 / MU:worker_c1#001@118-120 / MU:worker_c2#001@101-103`
- `join`：分别回到 `MU:main#004@184-187 / MU:main#006@192-195 / MU:main#008@199-202`

因此更适合把 `worker_c0/worker_c1/worker_c2` 的计算段权重调大，并把主线程反复执行的 `C10` 调小，避免串行段主导 makespan。

对应权值宏在源文件：

- `源文件/zhang2/zhang2.c` 顶部的 `#define C1..C16`

## 5. 修改后如何验证“关键路径变了”

推荐流程（在 `/home/chove/桌面` 目录执行）：

1) 重新跑测时：
`python3 -m mycallyplus_v1.pipeline.cli --base-dir mycallyplus_v1 timing --base-name zhang2 --level level2 --rule effective_line_merge`

2) 重新跑关键路径算法（例如 cpf）：
`python3 -m mycallyplus_v1.pipeline.cli --base-dir mycallyplus_v1 schedule --base-name zhang2 --level level2 --rule effective_line_merge --algo cpf`

3) 查看关键路径层（`cp_layers`）：
- `中间结果/zhang2/pipeline/schedule/level2/effective_line_merge/cpf/schedule.json`
