## 2. 本轮结构设计

本次 `zhang4.c` 采用如下结构：

- 三段关键链：
  - `critical_worker_1`
  - `critical_worker_2`
  - `critical_worker_3`
- 两条填充线程：
  - `fill_worker_1`
  - `fill_worker_2`
- 关键链通过 `sem_post/sem_wait` 串接。
- 真实计算都放在独立的 `pthread_mutex_lock/unlock` 保护段内。
- `main` 尽量只负责：
  - CPU 绑核
  - 初始化
  - 创建线程
  - `join`
  - 尾部一个较小计算段

设计意图：

- 让关键链尽早释放，并跨线程传播。
- 让填充线程足够重，在 FIFO 下更容易抢占两核 CPU。
- 让 `zhao2020` 有条件优先保护关键链，而不是被 `main` 串行主导。

## 5. 分块测时结果

`timing.json` 中最重的关键块如下：

- `MU:critical_worker_3#002@114-117 = 37157593216 ns`
- `MU:critical_worker_2#002@104-108 = 27279738874 ns`

- `MU:fill_worker_1#002@79-81 = 14189077319 ns`

说明：

- 关键链三段已经成为图上最主要的高权重路径。
- 两条填充线程也足够重，能够与关键链竞争 CPU。
- 这比 `zhang22` 更符合“关键链 + 非关键填充竞争”的实验目标。

## 8. 结论

本轮 `zhang4` 结果表明：

- “重新设计结构，让关键链更适合优先级调度”是有效的。
- 与 `zhang22` 相比，这版程序已经能让 `zhao2020` 在真实 runtime compare 中获得明显正收益。
- 当前收益不是由单纯调大权重得到的，而是由“结构 + 权重”共同决定的：
  - 关键链足够重
  - 填充线程也足够重
  - 关键传播跨线程发生
  - `main` 不再长期串行主导关键路径

一句话总结：

- `zhang4` 这版结构已经基本证明：只要 DAG 结构设计得更贴近 `zhao2020` 的优势场景，优先级调度可以稳定优于 FIFO。
