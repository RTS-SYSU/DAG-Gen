## 执行时间线 (2核, CFS)

```
时间(ms)  0    69   84  115  139  149  185       352  401  416     516     575  635  640  643
          |    |    |    |    |    |    |          |    |    |       |       |    |    |    |

详细时间线:

Phase 1 (0~69ms): main 独占
  核1: main:C8=30 (0→69ms, dur=69ms)
  核2: 空闲

Phase 2 (69~149ms): main + 3 worker 竞争 2 核
  核1: main:C9=40 (69→139ms) → main:C10=50 (139→185ms)
  核2: c0:C7=50 (70→149ms), c2:C1=15 (81→115ms), c1:C4=15 (84→118ms)
  ★ CFS 在核2上轮转 c0/c2/c1, 每个都被拖慢

Phase 3 (185~416ms): sem_post(s1,s2) 后, c1+c2+main 竞争 2 核
  c1:C5=400 (185→516ms, dur=331ms, 理论=172ms → 被拖慢 1.9x)
  c2:C2=200 (185→401ms, dur=217ms, 理论=107ms → 被拖慢 2.0x)
  main:C11=100 (197→352ms, dur=155ms, 理论=43ms → 被拖慢 3.6x)
  main:C12=50 (352→416ms, dur=64ms)
  ★ 3 个线程竞争 2 核, CFS 均分 → 每个得 2/3 核

Phase 4 (416~640ms): sem_post(s3) 后, c2:C3 + main 竞争
  c2:C3=300 (416→640ms, dur=224ms, 理论=113ms → 被拖慢 2.0x)
  main:C13=80 (516→575ms, dur=60ms)
  main:C14=80 (575→635ms, dur=60ms)
  ★ c2:C3 和 main:C13/C14 竞争 2 核

Phase 5 (640~643ms): 收尾
  main:C15=5 (640→643ms, dur=3.7ms)
```

## 关键观察

### 1. CFS 的 CPU 分配

| 时间段 | 就绪线程数 | 每线程 CPU 份额 | 影响 |
|--------|-----------|----------------|------|
| 0~69ms | 1 (main) | 100% | main 独占 |
| 69~149ms | 4 (main+c0+c1+c2) | 50% | c0/c1/c2 被拖慢 |
| 185~352ms | 3 (c1+c2+main) | 67% | c1/c2/main 都被拖慢 |
| 352~416ms | 2 (c1+c2) + main:C12 | ~67% | c1 继续被拖慢 |
| 416~516ms | 2 (c2+c1) | 100% 各占1核 | 无竞争 |
| 516~640ms | 2 (c2+main) | 100% 各占1核 | 无竞争 |

### 2. 权重 vs 实际耗时

| 段 | 权重 | 理论 dur_ms (按 C5 基准) | 实际 dur_ms | 膨胀比 | 原因 |
|----|------|------------------------|-------------|--------|------|
| c1:C5=400 | 400 | 172ms | 331ms | 1.92x | Phase3 被 c2+main 抢 CPU |
| c2:C2=200 | 200 | 86ms | 217ms | 2.52x | Phase3 被 c1+main 抢 CPU |
| main:C11=100 | 100 | 43ms | 155ms | 3.60x | Phase3 被 c1+c2 抢 CPU |
| c2:C3=300 | 300 | 129ms | 224ms | 1.74x | Phase4 被 main:C13/C14 抢 CPU |
| main:C8=30 | 30 | 13ms | 69ms | 5.31x | Phase1 包含 init_matrices() |
| c0:C7=50 | 50 | 22ms | 79ms | 3.59x | Phase2 被 main+c1+c2 抢 CPU |

### 3. 关键路径分析

实际关键路径: main:C8 → fork → main:C9 → main:C10 → sem_post → c2:C2 → (等 sem_post(s3)) → c2:C3 → join → main:C15

瓶颈: c2:C3=300 是最后完成的段 (640ms), main 必须等它完成才能跑 C15

### 4. 算法优化空间

如果算法给 c2 最高优先级 (因为 c2 是最终瓶颈):
- c2:C3 独占 1 核, 理论 dur=113ms (而非 224ms)
- 总时间可缩短约 100ms (从 643ms 到 ~540ms)

但问题是: c2 的 C3 段要等 sem_post(s3), 而 s3 在 main:C12 之后才 post。
所以真正的优化点在 Phase3: 让 main 尽快跑完 C11+C12 到达 sem_post(s3)。
