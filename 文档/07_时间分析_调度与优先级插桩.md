# 时间分析、调度与优先级插桩

## 1. 时间分析有两条主线

### 1.1 调用点级测时

实现位置：

- `time_analysis.py`

特点：

- 直接读取 `mycalls_meta_internal.json`
- 把计时代码插入到具体调用语句前后
- 输出调用点级 `time_result.json`、`metrics.json`、`thread_trace.json`

适合回答：

- 哪个调用点耗时多少
- 原始调用图节点如何带权

### 1.2 分段级测时

实现位置：

- `level1/time_analysis_level1.py`
- `pipeline/timing.py`

特点：

- 针对 Level-1 / Level-2 的 `segments.json`
- 在段边界插入 `SEG_BEGIN/SEG_END`
- 读取 `trace.*.csv`
- 汇总成 `timing.json`

适合回答：

- 哪个段的总时间、平均时间、次数是多少
- 分段 DAG 上如何做调度

## 2. 调用点级插桩逻辑

`time_analysis.py` 的关键处理包括：

- 扁平化 `mycalls_meta_internal.json`
- 解析出 `CallSite`
- 给源码补 `#include "time_stat.h"`
- 定位调用表达式边界
- 在调用前后插入 `TA_BEGIN` / `TA_END`
- 编译整个项目
- 运行程序并汇总结果

代码里还做了很多保护：

- 跳过编译器内部符号，如 `__stack_chk*`
- 避免重复插桩
- 尽量避开复杂控制语句、赋值与三目表达式

## 3. 分段级测时逻辑

`level1/time_analysis_level1.py` 和 `pipeline/timing.py` 的逻辑更直接：

1. 读取 `segments.json`
2. 只保留在 `dag_seg.json` 中实际参与边连接的 active segments
3. 拷贝整个源码目录到实验目录
4. 注入 `segtrace.*`、`prog_timer.*`、`wrap_main.c`
5. 对目标源码按段边界插桩
6. 编译并运行
7. 读取 `trace/trace.*.csv`
8. 汇总 `total_ns`、`avg_ns`、`min_ns`、`max_ns`

当前 pipeline 默认对同一组 segments 运行 10 次，并以这些运行结果汇总得到的 `avg_ns` 作为段级调度算法统一使用的节点权重；若调用方显式覆盖次数，则仍然统一读取该次测时结果中的 `avg_ns`。

## 4. 调度算法

### 4.1 `scheduler.py`

面向函数节点或带权 DOT，提供：

- DAG 拓扑排序
- 最长路径计算
- CPC 优先级计算
- 把权重与优先级回写到 DOT

### 4.2 `pipeline/algo/*`

面向分段 DAG，当前实现了六个算法：

| 算法 | 文件 | 思路 |
| --- | --- | --- |
| `lpf` | `pipeline/algo/lpf.py` | 按到汇点的关键路径长度排序 |
| `cpf` | `pipeline/algo/cpf.py` | 反复抽取关键路径层，按层分配优先级 |
| `heft` | `pipeline/algo/heft.py` | 零通信成本 HEFT，给出 processor assignment |
| `wcet_first` | `pipeline/algo/wcet_first.py` | 直接按节点 `avg_ns` 降序分配优先级 |
| `t_level` | `pipeline/algo/t_level.py` | 按 source 到当前节点的前向最长路径分数排序 |
| `zhao2020` | `pipeline/algo/zhao2020.py` | 依据 CPC 模型与 EA 规则分配优先级 |

所有算法最终都输出：

- `schedule.json`
- `priorities: {seg_id -> 1..99}`

## 5. 优先级插桩

### 5.1 Level-1 专用路径

实现位置：

- `level1/instrument_prio_level1.py`

做法：

- 给源码插入 `#include "prio_runtime.h"`
- 对 `compute` 段起始行插入 `l1_set_thread_prio_fifo(prio);`
- 同一插入点若有多个候选优先级，保留更高者

### 5.2 pipeline 插桩路径

实现位置：

- `pipeline/instrument.py`
- `pipeline/instrument_levelx.py`

模式：

- `specialized`：Level-1 默认复用 `instrument_prio_level1.py`
- `generic`：对任意 level 按 `start_line` 回写优先级
- `auto`：Level-1 走专用路径，Level-2/3 走通用路径

## 6. 与操作系统调度的关系

代码与 README 都强调了一点：

- 优先级最终通过 `SCHED_FIFO` / `pthread_setschedparam` 一类机制生效。
- 如果没有 `root` 或 `CAP_SYS_NICE`，优先级设置可能失败，甚至只带来额外开销。

因此实验结果必须区分：

- 调度算法逻辑是否正确
- 操作系统是否真的接受了线程优先级
