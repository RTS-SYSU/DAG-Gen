# 代码结构与模块说明

## 1. 入口层

| 文件 | 说明 |
| --- | --- |
| `__main__.py` | 包入口，只调用 `cli.main()` |
| `cli.py` | 统一入口，支持 `gui`、`generate`、`describe`、`pipeline` |
| `run_gui.py` | 历史 GUI 启动包装器，仍使用 `mycallyplus_v1` 前缀 |

`cli.py` 的分发关系如下：

- `gui` -> `ui.gui.main`
- `generate` -> `generation.legacy.main`
- `describe` -> `visualization.viewer.main`
- `pipeline` -> `pipeline.cli.main`

## 2. 生成层

| 目录/文件 | 说明 |
| --- | --- |
| `generation/legacy.py` | 最重要的旧链路入口，负责解析、建图、导出 |
| `generation/parser.py` | 简化版 RTL 解析器 |
| `generation/builder.py` | 构建反向索引 |
| `generation/source_binder.py` | 用 C 源码兜底 create/join 绑定 |
| `generation/exporters.py` | 导出 DOT 与 `circle.txt` |
| `generation/thread_map.py` | join 边解析与线程补边 |
| `generation/renderer.py` | 现代化渲染接口 |

这里有一个重要现实：`generation/parser.py`、`generation/model.py`、`generation/builder.py` 更像“现代化抽象层”，而真正承担主工作量的仍然是 `generation/legacy.py`。

## 3. 基础模型层

| 目录/文件 | 说明 |
| --- | --- |
| `core/model.py` | `Function`、`ThreadInfo`、`CallGraph`、`RenderOptions` |
| `core/parser.py` | 与 `generation/parser.py` 类似的最小解析器 |
| `core/thread_map.py` | 线程补边与 join 解析 |
| `core/threads.py` | 线程边推导 |
| `core/func_ranges.py` | 从源代码中提取函数起止范围 |
| `core/control_flow.py` | 条件前缀映射 |

`core/*` 与 `generation/*` 存在一定程度的镜像关系，说明项目在做“旧逻辑向新接口迁移”，但还未完全收敛。

## 4. 分块层

| 目录/文件 | 说明 |
| --- | --- |
| `level1/segment_dag.py` | Level-1 stage1 分块与段 DAG |
| `level2/segment_dag_level2.py` | Level-2 分块规则实现 |
| `level2/merge_post_wait_dag.py` | 把 `sem_post -> sem_wait` 补入图 |

职责划分：

- `level1` 关注 `pthread_create` / `pthread_join` 切点。
- `level2` 在此基础上引入 `sem_post` / `sem_wait` / `mutex` 规则和“有效代码行相邻合并”。

## 5. 测时与调度层

| 文件/目录 | 说明 |
| --- | --- |
| `time_analysis.py` | 调用点级自动插桩、编译、运行、统计 |
| `scheduler.py` | DAG 最长路径、CPC 优先级和 DOT 标注 |
| `level1/time_analysis_level1.py` | 段级测时 |
| `level1/instrument_prio_level1.py` | Level-1 优先级插桩 |
| `level1/lpf_segment.py` | 段级 LPF 优先级分配 |
| `level1/lpf_thread.py` | 线程级 LPF 优先级分配 |

## 6. pipeline 层

| 文件 | 说明 |
| --- | --- |
| `pipeline/cli.py` | stage 式命令行入口 |
| `pipeline/collector.py` | 校验并整理上游输入 |
| `pipeline/runner.py` | 统一调度 collect/blocks/timing/schedule/instrument |
| `pipeline/rules_registry.py` | 分块规则注册表 |
| `pipeline/algo_registry.py` | 调度算法注册表 |
| `pipeline/timing.py` | pipeline 的段级测时 stage |
| `pipeline/schedule.py` | pipeline 的调度 stage |
| `pipeline/instrument.py` | pipeline 的优先级插桩 stage |

当前已注册的规则：

- `level1/stage1_create_join`
- `level2/effective_line_merge`
- `level3/placeholder_level3`

当前已注册的算法：

- `lpf`
- `cpf`
- `heft`
- `wcet_first`
- `t_level`
- `zhao2020`

## 7. 交互与展示层

| 文件 | 说明 |
| --- | --- |
| `ui/gui.py` | 主 GUI 工作台 |
| `visualization/viewer.py` | 独立图查看器 |
| `filter_dot.py` | DOT 节点名去噪 |
| `time_charts.py` | 时间结果可视化 |

`ui/gui.py` 不只是界面层，它还直接调用生成、分块、调度和运行脚本，因此带有明显的“工作台控制器”属性。

## 8. 工具与实验层

| 目录/文件 | 说明 |
| --- | --- |
| `tools/` | 运行时对比 GUI、报告汇总脚本、辅助脚本 |
| `experiment/` | 实验结果沉淀 |
| `中间结果/` | 本地运行中间产物 |
| `配置文件/` | 示例配置 |
| `源文件/` | 示例源码/Makefile |
