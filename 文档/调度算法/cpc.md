1) 先构造 CPC 模型：把 DAG 划分为“提供容量的关键路径段”+“消耗容量的并行节点组”
1.1 找全局关键路径 λ*

先在 DAG 里找最长路径（通常按节点 WCET 累加的最长路径），记为 λ*。这条路径是整个 DAG 的 “critical path”。

1.2 把 λ* 切成若干个 provider（容量提供者）集合 Θ*

论文不是把 λ* 上每个节点都单独当关键节点，而是把它们合并成若干段 θ*_i（provider）：

沿 λ* 的拓扑顺序走；

如果下一个关键节点 只有一个前驱且就是当前节点（pre(v_{j+1}) = {v_j}），就把它并进同一个 provider 段；

一旦遇到 join（前驱不止一个）或不是直连，就切段，开始新的 provider。

所以 Θ* 是一串 provider 段：θ*_1, θ*_2, ...

1.3 给每个 provider 关联一个 consumer 集合 F(θ*_i)

对每个 provider θ*_i，算法构造一组“能与它并行执行、但可能影响后续 provider 启动”的节点集合 F(θ*_i)（消费者组）。这一步是 Algorithm 1 的主要输出之一。

直观理解：

provider 在执行时占用 1 个核；

其余 (m−1) 个核可以并行跑 consumer；

但如果 consumer 组里有节点拖得太晚，会推迟下一个 provider 的开始，因此需要在优先级上“管住它”。

2) 真正的“优先级计算”：Algorithm 2（EA）逐步分配 pj

Algorithm 2 的输入就是 Θ* 和所有 consumer 集合 F(θ*_i)。优先级用整数 pj 表示，初始化为 -1，然后从 pmax 往下分配（越大优先级越高）。

规则 Rule 1：先给所有 provider（关键路径段）最高优先级

Algorithm 2 第 2 行：

对所有 vj ∈ Θ*（注意这里是 provider 内部的节点集合，论文实现里通常就是把关键路径段里的节点都算在 Θ* 的元素里），按顺序分配：

pj = p; p = p - 1

含义很直接：

关键路径（provider）优先，确保 critical path first execution（CPFE）；

而且一般是“越靠前的 provider 节点拿到越高的优先级”，避免关键路径被拖慢。

规则 Rule 2：对每个 consumer 组，反复挑“最长局部路径”先分配

Algorithm 2 第 4–18 行：对每个 provider θ*_i（拓扑顺序）处理它的 F(θ*_i)，直到该集合为空。

关键步骤是：

(a) 在 F(θ*_i) 里找一个“局部最长路径” λ_{ve}

先选一个终点 ve，它必须满足在 F(θ*_i) 的诱导子图里是“局部末端”（suc(ve)=∅），然后取使得“到它的最长路径长度”最大的那个 ve。

论文里写成：

ve = argmax_{ve} { l_e(F(θ*_i)) | suc(ve)=∅ }

其中 l_e(F) 可以理解为：在子图 F 中，到 ve 的最长路径长度（通常是 WCET 和）。

然后通过回溯构造整条路径 λ_{ve}：不断从 ve 往前找前驱里“局部最长”的那个，直到路径起点。

直观含义：

在一个 consumer 组里，先把最重/最长的那条依赖链提到前面执行；

这样它更不容易在 provider 结束后还没跑完，从而推迟下一个 provider。

(b) 如果这条局部最长路径和剩余节点存在“复杂依赖”，就递归再做 CPC

Algorithm 2 第 10–13 行是整个方法最关键的“递归触发条件”：

如果在 λ_{ve} 中存在某个节点 vj 满足 |pre(vj)| > 1

这表示出现 join（多前驱汇合），意味着 λ_{ve} 与 F(θ*_i)\λ_{ve} 之间存在依赖耦合，不能简单按“独立路径”处理；

那就对 F(θ*_i) 再构造一个“内层 CPC”：

{Θ*', Θ'} = CPC(F(θ*_i), λ_{ve})

然后递归调用 EA(Θ*', Θ')

break（把当前 F 的处理交给递归层完成）

直观含义：

consumer 组内部如果还包含“带依赖结构的子 DAG”，就再做一层 CPC 分解；

保证在更细粒度上仍然满足“最长链优先、关键链优先”，而不是粗暴地把节点当成可随意并行。

(c) 否则：把这条局部最长路径当作“独立链”直接按 Rule 3 分配

如果没有 join（|pre(vj)| 都不大于 1），论文认为 λ_{ve} 是一条相对独立的局部链，就执行 Rule 3（Algorithm 2 第 16–17 行）：

对 vj ∈ λ_{ve}：pj = p; p = p - 1

从 F(θ*_i) 中移除这条路径：F(θ*_i) = F(θ*_i) \ λ_{ve}

回到 while 循环，继续找下一条局部最长路径……

3) 总结成一句话：它的“优先级计算逻辑”是什么？

优先级不是“算出来”的，而是“分配出来”的：

全局先锁定关键路径 λ*，把它切段成 providers（Θ*）

providers 全拿最高优先级（Rule 1）

对每个 provider 的并行 consumer 组 F：

反复取 局部最长路径 λ_{ve} 先分配优先级（Rule 2/3）

一旦发现 consumer 组内部还有复杂依赖（join），就对该子图 递归做 CPC + EA

直到所有节点 pj 都被赋值

所以它本质是一个 “Critical-path-first + Longest-chain-first + 递归分解依赖” 的优先级分配框架，而不是单次打分排序。
