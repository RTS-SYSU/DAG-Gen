# 运行方式与产物目录

## 1. 运行环境

从源码和 README 看，当前项目的基本依赖是：

- Python 3.8+
- `gcc`
- `graphviz` 的 `dot`
- 运行 GUI 时需要 `tkinter`
- 显示 PNG 时最好安装 `Pillow`

## 2. 当前仓库命名现状

仓库目录名已经是 `ScratchDAG`，但代码内部仍大量保留 `mycallyplus_v1` 导入前缀。

本次源码验证结果：

| 项目 | 结果 |
| --- | --- |
| `import ScratchDAG` | 成功 |
| `import ScratchDAG.generation.legacy` | 成功 |
| `import ScratchDAG.pipeline.cli` | 失败，缺少 `mycallyplus_v1` |
| `import ScratchDAG.ui.gui` | 失败，缺少 `mycallyplus_v1` |

因此，文档里的运行建议分成两类：

- 可直接按当前目录运行的命令
- 需要先解决包名兼容问题后再运行的命令

## 4. 建议的实际使用方式

在当前仓库状态下，最稳妥的使用顺序是：

1. 先用 `generation/legacy.py` 生成基础 DAG 产物。
2. 再用 `level1/*`、`level2/*`、`scheduler.py` 或阅读 `pipeline/*` 产物目录。
3. 若要真正启用 `pipeline` CLI 或 GUI，需要先统一包名导入问题。

## 5. legacy 产物目录

最重要的基础目录是：

```text
中间结果/<base_name>/
```

其中常见子目录包括：

| 目录 | 说明 |
| --- | --- |
| `配置文件/` | DOT、`circle.txt`、输入备份 |
| `生成dag图/` | `dag.dot/png`、`functions_full.json`、`functions_ranges.json`、`debug/*` |
| `时间分析/` | 调用点级时间分析结果 |
| `时间分析_cpc/` | 带优先级的时间分析结果 |
| `调度算法/` | 最长路径、CPC 和对比结果 |
| `level1/` | Level-1 分块与相关实验 |
| `level2/` | Level-2 分块与中间图 |
| `pipeline/` | 新模块化 stage 产物 |

## 6. pipeline 产物目录

`pipeline` 使用统一层次：

```text
中间结果/<base_name>/pipeline/
├── block_info.json
├── derived/
├── blocks/<level>/<rule>/
├── timing/<level>/<rule>/
├── schedule/<level>/<rule>/<algo>/
└── instrument/<level>/<rule>/<algo>/
```

对应阶段含义：

- `block_info.json`：collector 汇总的输入元信息。
- `derived/`：从 `circle.txt` 或内部元数据派生出的补充信息，如 `sem_pairs.json`。
- `blocks/`：分块结果。
- `timing/`：段级测时结果。
- `schedule/`：调度结果。
- `instrument/`：插桩后的源码和元数据。

## 7. 关键输入文件映射

| 文件 | 典型来源 | 下游消费者 |
| --- | --- | --- |
| `dag.dot` | `generation/legacy.py` | viewer、Level-2、scheduler |
| `functions_full.json` | `generation/legacy.py` | Level-1、Level-2 |
| `functions_ranges.json` | `generation/legacy.py` + `core/func_ranges.py` | Level-1、Level-2 |
| `mycalls_meta_internal.json` | `generation/legacy.py` | `time_analysis.py`、Level-1、Level-2 |
| `circle.txt` | `generation/exporters.py` | viewer、Level-2、collector |
