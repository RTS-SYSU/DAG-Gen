# ScratchDAG 开发规则约定

## 1. 目标
- 以“先理解全局、再分阶段推进、每阶段留痕”为核心原则推进项目。
- 所有阶段产出必须可追踪、可复现、可交接。
- 需求以单一入口持续更新，避免口头需求漂移。

## 2. 开发总流程（强制）
1. 读取当前需求（`mycallyplus_v1/当前开发需求/需求说明.md`）。
2. 对需求做结构化确认（目标、范围、约束、验收标准、未决问题）。
3. 执行阶段任务（代码/脚本/实验/分析）。
4. 完成阶段文档沉淀（阶段成果文档 + 结果文件路径）。
5. 更新阶段状态（进行中/已完成/阻塞）并记录下一步。

## 3. 分阶段约定
- 每个阶段必须有唯一编号：`S01`、`S02`、`S03`...
- 每个阶段必须有一份阶段成果文档：
  - 路径：`mycallyplus_v1/文档/阶段成果/SXX_阶段名.md`
  - 必含章节：目标、输入、实现、结果、验证、风险、下一步。
- 阶段完成后必须补充：
  - 关键命令
  - 输出文件路径
  - 与上一阶段的差异

## 4. 需求管理约定（单一事实来源）
- 固定需求入口文件：`mycallyplus_v1/当前开发需求/需求说明.md`
- 你（用户）每次修改需求后，下一轮我都会优先重新读取该文件再执行。
- 需求文件建议结构：
  - 背景
  - 本轮目标
  - 明确不做
  - 约束
  - 验收标准
  - 未决问题

## 5. 交互约定
- 我在每次实现前会先复述需求理解，再开始改动。
- 若需求与现有实现冲突，我会先指出冲突点和可选方案，再执行你确认的方案。
- 若信息不足，我先提最少必要问题，不做隐含假设。
- 默认最小读取集：优先读取 `mycallyplus_v1/文档/代码段切割方法/level2级分块.md` 的 **B. 本轮变更**；必要时回退到 **A. 稳定规则**。
- 规则冲突优先级：**本轮变更 > 稳定规则 > 旧阶段文档**。

## 6. 文档沉淀约定
- 除代码外，所有重要结果必须在文档中可定位。
- 文档中所有路径使用仓库相对路径，便于复现。
- 若实验流程变更，必须更新对应流程文档并标记变更日期。
- 文档更新触发器：仅当用户明确发出口令 `同步文档` / `阶段收敛` / `会话交接` 时，才同步更新阶段文档与规则文档。
- 非触发状态：实现完成后只回报结果与路径，不自动更新其他文档。

## 7. 执行边界
- 未经明确要求，不修改无关模块。
- 未经明确要求，不重命名既有接口/目录。
- 若出现阻塞，先给出最小可行替代路径，再等待确认。

## 8. 生效说明
- 本文档从创建时起生效，后续以“最新版本”为准。
