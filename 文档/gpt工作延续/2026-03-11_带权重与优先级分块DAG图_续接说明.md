## 2. 已完成的正确性检查

已经对 `zhang1` 的以下两套插桩结果做过人工核对：

- `/home/chove/Desktop/ScratchDAG/中间结果/zhang1/pipeline/instrument/level2/effective_line_merge/t_level`
- `/home/chove/Desktop/ScratchDAG/中间结果/zhang1/pipeline/instrument/level2/effective_line_merge/wcet_first`

核对结论：

### 2.1 `wcet_first`

`schedule.json` 与 `timing.json.weights[*].avg_ns` 完全一致。

即：

- 分数 = `avg_ns`
- 按分数降序排序
- 同分按 `seg_id` 升序稳定打破平局
- 再映射到 `99..1`

### 2.2 `t_level`

`schedule.json` 与按 `dag_seg.json` 重算得到的前向最长路分数完全一致。

定义：

```text
t_level(v) = max_{u in pred(v)} (t_level(u) + cost(u))
source 节点 = 0
cost = avg_ns
```

同样是：

- 先按 `t_level score` 降序
- 同分按 `seg_id` 升序
- 再映射到 `99..1`

### 2.3 插桩位置

已检查 `source_instrumented.c` 中 `l1_set_thread_prio_fifo(...)` 的插入值，与：

- `segments.json` 的 `start_line`
- `schedule.json.priorities`

是对齐的，没有发现“优先级算对但回写错段”的问题。

## 3. 用户当前的新需求

用户希望在现有“分块 DAG”基础上，多生成一张图，便于人工检查：

- 每个节点显示该段的权重
- 每个节点显示该算法分配的优先级

目标是能直接看一张图完成人工核对，而不是分别打开：

- `dag_seg.json`
- `timing.json`
- `schedule.json`

## 4. 建议下一个窗口继续做的事情

### 4.1 目标图的建议内容

建议新增一张 DOT / PNG：

- 输入：
  - `blocks/<level>/<rule>/dag_seg.json`
  - `timing/<level>/<rule>/timing.json`
  - `schedule/<level>/<rule>/<algo>/schedule.json`
- 输出：
  - `schedule/<level>/<rule>/<algo>/dag_seg_annotated.dot`
  - `schedule/<level>/<rule>/<algo>/dag_seg_annotated.png`

建议每个节点标签至少包含：

- `seg_id`
- `avg_ns`
- `prio`

例如：

```text
MU:main#007@222-231
avg_ns=19980
prio=94
```

如果空间允许，也可以加：

- `function`
- `kind`

但优先级检查最关键的是：

- 节点 ID
- 权重
- 优先级

### 4.2 最合适的接入点

最建议接在 `pipeline/schedule.py` 这一层。

原因：

- `run_schedule()` 同时已经拿到了：
  - `dag_json`
  - `segments_json`
  - `timing_json`
  - `schedule_json`
- 图的输出目录正好也是：
  - `中间结果/<base>/pipeline/schedule/<level>/<rule>/<algo>/`

不建议接到 `pipeline/instrument.py`，因为那一层已经是“源码回写”阶段，图本质上属于“调度结果可视化”。

### 4.3 建议新增的实现位置

建议新增一个小工具模块，例如：

- `pipeline/schedule_render.py`

建议提供一个函数，例如：

```python
def render_annotated_schedule_dag(
    *,
    dag_json: Dict,
    segments_json: Dict,
    timing_json: Dict,
    schedule_json: Dict,
) -> str:
    ...
```

输出 DOT 字符串。

然后在 `pipeline/schedule.py` 中：

1. 生成 `schedule.json`
2. 调用上面的 render 函数
3. 写出：
   - `dag_seg_annotated.dot`
   - `dag_seg_annotated.png`

渲染 PNG 可复用 `pipeline/runner.py` 里 `_render_dot()` 的思路，或者直接在 `pipeline/schedule.py` 里用 `dot -Tpng`。

### 4.4 建议的节点标签格式

建议使用 Graphviz `label` 多行文本：

```text
{seg_id}\navg_ns={avg_ns}\nprio={prio}
```

注意：

- `avg_ns` 来自 `timing_json["weights"][seg_id]["avg_ns"]`
- `prio` 来自 `schedule_json["priorities"][seg_id]`
- 缺字段时要显式报错，不要静默跳过
