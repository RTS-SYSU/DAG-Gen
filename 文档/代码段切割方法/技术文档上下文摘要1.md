【技术上下文摘要】

目标：在 mycallyplus_v1 内实现 Level‑1 段级流程：标准 DAG → Stage‑1 切段 → 段级 DAG → 段级测时 → 段级 LPF 优先级 → prio 插桩生成对照实验（baseline/prio）→ 输出对比文件；并集成到 GUI（时间分析区子功能）。
阶段范围：Level‑1/Stage‑1 只处理 cut points = pthread_create*、pthread_join*；条件节点/热点段暂不做（记录在文档）。
<base> 规则：优先用源 .c 文件名 stem；若缺失源文件则用 .233r.expand 去掉后缀后的前缀作为 <base>。
源文件约束：所有插桩/优先级修改不得改写原始源文件；必须复制到 mycallyplus_v1/中间结果/<base>/level1/experiments/.../project/ 的工程副本内再改写、编译、运行。
Level‑1 统一目录结构：mycallyplus_v1/中间结果/<base>/level1/
stage1/：segments_stage1.json、dag_stage1_seg.json、dag_stage1_seg.dot（可渲染 png）
timing/<project>/：time_result_seg.json、trace/trace.<tid>.csv、time_analysis_level1.log
schedule/lpf_segment/：schedule_seg.json；（可选）schedule/lpf_segment_entry/：只对线程入口函数段分配
experiments/lpf_segment_<timestamp>/<project>/：baseline/project/...、prio/project/...、compare.json
functions_ranges.json：
路径：mycallyplus_v1/中间结果/<base>/生成dag图/functions_ranges.json
触发：运行 mycallyplus_v1.generation.legacy 且提供 --source-file <xxx.c>
实现：mycallyplus_v1/core/func_ranges.py（去注释/字符串、函数定义定位、{} 配对）
规则：@instanceN 归一到 base_name；__stack_chk_fail* 忽略
Level‑1 范围：level1_start_line=first_stmt_line(缺失则 body_start_line)；level1_end_line=last_stmt_line(缺失则 end_line)
Stage‑1 段定义 segments_stage1.json：
路径：mycallyplus_v1/中间结果/<base>/level1/stage1/segments_stage1.json
生成：mycallyplus_v1/level1/segment_dag.py（也由 legacy --level1-stage1 调用）
输入：生成dag图/functions_full.json、生成dag图/functions_ranges.json、生成dag图/debug/mycalls_meta_internal.json
切段：在 [level1_start_line, level1_end_line] 内按 create/join 行号切 compute 段 + 单行 create/join 段
seg_id 命名：compute=THR:<func>#<idx>@<start>-<end>；create=CRT:<func>#<idx>@L<line>；join=JON:<func>#<idx>@L<line>
Stage‑1 段级 DAG dag_stage1_seg.json：
路径：mycallyplus_v1/中间结果/<base>/level1/stage1/dag_stage1_seg.json
节点：来自 segments_stage1.json.segments[*].seg_id
边三类：intra（函数内段顺序）、create（create 段→entry_fn 首段）、join（entry_fn 末段→join 段）
entry_fn 获取：functions_full.json 的 mycalls 结构（pthread_createX 后紧跟线程入口函数节点）
join 映射：functions_full.json.myinfo 中 join_node->tid_var；tid_var->entry_fn 需全局扫描所有函数 myinfo（支持链式创建 tc1..tc4）
段级退出点：用“函数最后一个段”，不使用标准 DAG 的 __stack_chk_fail* tail
段级测时（独立模块，不复用 time_analysis.py）：
入口：mycallyplus_v1/level1/time_analysis_level1.py
runtime：mycallyplus_v1/level1/segtrace.{h,c}（段不嵌套假设：TLS 单槽；每线程一个 trace.<tid>.csv）
插桩：按 segments_stage1.json 段边界插 SEG_BEGIN/SEG_END；不安全边界跳过并记录 warning；多行语句暂不处理并记录文档
输出：time_result_seg.json（seg_id→total_ns等）+ trace
段级 LPF 优先级：
入口：mycallyplus_v1/level1/lpf_segment.py
权重：create/join 段=0；compute 段=time_result_seg.json[seg_id].total_ns
汇点：main 最后一个段（已确认）
输出：schedule_seg.json（priorities: {seg_id: prio_int}），权重为 0 的段不分配；可选 --only-entry-functions 输出到 schedule/lpf_segment_entry/
对照实验（baseline vs prio）与总时间测量：
入口：mycallyplus_v1/level1/instrument_prio_level1.py
baseline：源代码副本不改（不插入优先级/不插入段边界/不插入测时代码）
prio：只在源代码副本内插入每个 compute 段起始行的 l1_set_thread_prio_fifo(prio)；同一行多段命中去重（保留最高优先级）
总时间测量：不改源代码；使用链接期 -Wl,--wrap=main + wrap_main.c + prog_timer.{h,c} 输出 PROGRAM_TOTAL_NS=<ns> 到 stderr；PROG_BEGIN() 内注册 atexit(PROG_END)
权限检测：mycallyplus_v1/level1/prio_runtime.h 在 pthread_setschedparam 失败时输出 L1_PRIO_SET_FAILED...；compare.json 记录 prio_set_failed
输出：compare.json（baseline_total_ns/prio_total_ns/delta_total_ns 等）
GUI 集成：
位置：mycallyplus_v1/ui/gui.py 时间分析子功能新增按钮 段级时间分析（Level-1）
输入来自状态区：state.source_file（.c）+ state.expand_file（.expand）
一键顺序固定：legacy(--source-file,--level1-stage1) -> 渲染段级DAG png -> 段级测时 -> lpf_segment -> instrument_prio_level1 -> compare.json
默认展示：段级 DAG png；若 prio_set_failed 则弹窗提示需要 root/CAP_SYS_NICE
