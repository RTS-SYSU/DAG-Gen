# 07. 开发与测试指南

## 7.1 环境准备
- OS：推荐 Linux / WSL。Windows 需安装 Graphviz 并保证 `dot` 可执行。
- Python：3.8+
- 依赖：`pip install -r requirements.txt`（networkx、pydot、Pillow 等）
- GCC：支持 `-fdump-rtl-expand`
- Graphviz：GUI/Viewer 渲染 PNG 必需

## 7.2 目录与运行
- 根目录：`/path/to/mycallyplus_v1`
- 统一启动 GUI：`PYTHONPATH=. python3 -m mycallyplus_v1`
- CLI 生成：`PYTHONPATH=. python3 -m mycallyplus_v1.generation.legacy --threads-only --output-base mycallyplus_v1 <expand>`
- 时间分析：`PYTHONPATH=. python3 -m mycallyplus_v1.time_analysis --source <src> --meta <mycalls_meta_internal.json>`

## 7.3 示例（time_analysis.c）
1. **生成 expand**  
   ```
   cd mycallyplus_v1/源文件/time_analysis
   gcc -fdump-rtl-expand -c time_analysis.c -o /tmp/time_analysis.o
   ```
2. **生成 DAG**  
   ```
   PYTHONPATH=. python3 -m mycallyplus_v1.generation.legacy \
     --threads-only --source-file mycallyplus_v1/源文件/time_analysis/time_analysis.c \
     --output-base mycallyplus_v1 \
     mycallyplus_v1/中间结果/time_analysis/配置文件/time_analysis.c.233r.expand
   ```
3. **运行时间分析**  
   ```
   PYTHONPATH=. python3 -m mycallyplus_v1.time_analysis \
     --source mycallyplus_v1/源文件/time_analysis/time_analysis.c \
     --meta mycallyplus_v1/中间结果/time_analysis/生成dag图/debug/mycalls_meta_internal.json
   ```
4. **调度算法（最长路径）**  
   - GUI：“调度算法 → 生成最长路径”  
   - 或 CLI（参考 scheduler 模块使用示例）

## 7.4 开发建议
- **调试 legacy**：可打开 `--debug`，查看 `中间结果/<base>/生成dag图/debug/` 下的快照（`post_parse`、`control_prefix` 等）。
- **GUI 调试**：在终端启动 `PYTHONPATH=. python3 ui/gui_debug.py`（如有），或直接 `python -m mycallyplus_v1`。使用 `print`/log 观察 state。
- **时间分析问题**：查看 `time_analysis.log`，定位插桩失败原因；确认 `mycalls_meta_internal.json` 是否含 `file/line`。
- **调度算法验证**：可使用 `scheduler.py` 直接调用函数（见模块内 docstring），或读取 `调度算法/<strategy>/schedule.json` 检查结果。

## 7.5 常见问题
- **未生成 circle.txt**：需先执行“生成配置文件”或 `legacy --export-txt`。
- **调度算法无按钮**：确保运行的是 `mycallyplus_v1` 包而非旧版本。
- **time_result.json 空**：确认程序运行成功、插桩点存在、日志无报错。
- **DOT 渲染失败**：检查 Graphviz 是否安装、`dot -V` 是否正常。

## 7.6 提交与同步
- 若需要保留旧版本，可在根目录复制一份（如 `cp -r mycallyplus mycallyplus_v1`）。
- 所有修改建议在 `mycallyplus_v1` 目录内进行，避免影响原仓库。
- 文档更新统一放入 `文档/系统架构/` 或相关子目录，方便 LLM/新人阅读。
