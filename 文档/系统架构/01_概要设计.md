# 01. 概要设计

## 1.1 工具定位
MycallyPlus 是一个面向多线程 C/C++ 项目的 **调用图生成 + 可视化 + 时间分析 + 调度策略实验** 平台，支持：
- 从 GCC RTL `.expand` 或源文件解析函数调用、条件节点、线程 create/join 关系；
- 生成 DOT/PNG、互斥锁/信号量/Tarjan 图，提供 GUI 交互查看；
- 通过时间分析（动态插桩）获得每个节点的执行耗时，再驱动调度算法分析、最长路径插桩等高级功能。

## 1.2 高层组件
```
┌────────────┐      ┌────────────────┐      ┌──────────────────┐
│ generation │ ---> │    中间结果    │ ---> │ visualization/UI │
└────────────┘      └────────────────┘      └──────────────────┘
       │                    │                         │
       │                    ├── 配置文件 (DOT/circle/expand)
       │                    ├── 生成dag图 / 查看条件节点 / 调度算法
       │                    └── 时间分析/插桩工程
       │
       └── time_analysis (插桩&运行) ──> 调度算法 (最长路径等策略)
```

### 核心模块职责
- **generation/legacy.py**：解析 `.expand`、生成调用图 DOT（threads/full）、导出 circle.txt、写入 debug 快照。
- **ui/gui.py**：统一 GUI，驱动“生成 DAG、条件节点、源码调用图、互斥锁/信号量、时间分析、调度算法”等功能。
- **visualization/viewer.py**：查看器，独立加载 DOT/TXT 并生成多种视图。
- **time_analysis.py**：按 `mycalls_meta_internal.json` 插桩/编译/运行，输出 `time_result.json`、`thread_trace.json`。
- **scheduler.py**：计算最长路径、构建带权 DOT、高亮关键路径、生成调度策略输出。

## 1.3 主要数据流
1. **生成阶段 (Generation)**  
   输入 `.expand`/`.c` → legacy 解析 → `中间结果/<base>/配置文件/` 写入 `<base>_threads.dot`、`<base>_full.dot`、`circle.txt`、`*.expand`、`*.c` 等；`中间结果/<base>/生成dag图/` 写入 `dag.dot/png`、debug JSON。
2. **可视化阶段 (Visualization/UI)**  
   GUI/Viewer 从 `中间结果/<base>/配置文件/` 读取 DOT/TXT，按功能复制到各自目录（生成 dag 图、条件节点、互斥锁/信号量等），生成 PNG/报告。
3. **时间分析 & 调度**  
   `mycalls_meta_internal.json`（debug 目录）+ 源文件 → `time_analysis` 插桩并运行 → `中间结果/<base>/时间分析/<project>/time_result.json`；  
   `time_result.json` + DAG DOT → `scheduler` 计算策略/最长路径 → `中间结果/<base>/调度算法/<strategy>/dag_highlight.dot/png`。
4. **最长路径插桩**  
   `longest_path.json` + `mycalls_meta_internal.json` → 仅对关键节点插桩 → `时间分析_lp` 目录 → `longest_path_compare.{json,txt}`。

## 1.4 环境约定
- 启动：`PYTHONPATH=. python3 -m mycallyplus_v1`（GUI），或 `python3 -m mycallyplus_v1.generation.legacy ...`（CLI）。
- 目录根：建议在项目根执行命令，`--output-base` 默认为 `mycallyplus_v1`。
- 所有新输出均在 `中间结果/<base>/...` 下，`配置文件/<base>/` 仅兼容旧数据读取，不再写入。
