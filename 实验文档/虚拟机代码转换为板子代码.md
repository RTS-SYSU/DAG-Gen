# 虚拟机代码转换为板子代码

## 背景

`粗略实验使用文件/zhang{1,2,3}` 下的 instrument 产物是在虚拟机上生成的旧格式，需要转换为符合约定术语 v3.0 的新格式，才能在 RK3588 板子上用 `runtime_compare` 跑实验。

## 旧格式（虚拟机产物）

```
pipeline/instrument/level2/effective_line_merge/
├── cpf/
│   ├── source_instrumented.c   ← 含 l1_set_thread_prio_fifo() 优先级插桩，无测时
│   ├── source_original.c       ← 纯源文件，无插桩无测时
│   └── instrument_meta.json
├── heft/
├── lpf/
├── t_level/
├── wcet_first/
└── zhao2020/
```

问题：
- 没有 `result/` 和 `timing/` 两级分类目录
- 没有 CFS、FIFO 两个对照组
- 没有 `MAIN_ELAPSED_S` 测时代码
- `sched_setaffinity` 绑的是虚拟机小核 0-3，板子上应绑大核 6-7

## 新格式（板子标准，v3.0）

```
pipeline/instrument/level2/effective_line_merge/
├── result/                         ← 不含测时的版本
│   ├── CFS/CFS.c                  ← 纯源文件，默认 CFS 调度
│   ├── FIFO/FIFO.c                ← 源文件 + main 开头 l1_set_thread_prio_fifo(99)
│   ├── cpf/cpf.c                  ← 各段有不同优先级
│   ├── heft/heft.c
│   ├── lpf/lpf.c
│   ├── t_level/t_level.c
│   ├── wcet_first/wcet_first.c
│   └── zhao2020/zhao2020.c
└── timing/                         ← 在 result 基础上加测时代码
    ├── CFS/CFS.c
    ├── FIFO/FIFO.c
    ├── cpf/cpf.c
    ├── heft/heft.c
    ├── lpf/lpf.c
    ├── t_level/t_level.c
    ├── wcet_first/wcet_first.c
    └── zhao2020/zhao2020.c
```

## 转换规则

### 1. 绑核修改（所有版本通用）

将旧的小核绑定：
```c
CPU_SET(0, &set);
CPU_SET(1, &set);
CPU_SET(2, &set);
CPU_SET(3, &set);
```

替换为大核绑定：
```c
CPU_SET(6, &set);
CPU_SET(7, &set);
```

### 2. 生成 CFS 版本

基于 `source_original.c`（任意算法目录下的都一样）：
- 去掉 `#include "prio_runtime.h"`
- 去掉所有 `l1_set_thread_prio_fifo(...)` 调用（source_original 本身就没有，确认即可）
- 修改绑核为 6,7

### 3. 生成 FIFO 版本

基于 `source_original.c`：
- 保留 `#include "prio_runtime.h"`（如果没有则添加）
- 在 main 函数体开头（`sched_setaffinity` 之前）插入 `l1_set_thread_prio_fifo(99);`
- 修改绑核为 6,7

### 4. 生成各算法版本（cpf/heft/lpf/t_level/wcet_first/zhao2020）

基于各自的 `source_instrumented.c`：
- 保留已有的 `l1_set_thread_prio_fifo(N)` 优先级插桩不变
- 修改绑核为 6,7

### 5. 生成 timing 版本（对以上 8 个版本各做一份）

在 result 版本基础上，添加 `MAIN_ELAPSED_S` 测时代码：

main 函数开头（第一行）插入：
```c
struct timespec ts_main_begin, ts_main_end;
clock_gettime(CLOCK_MONOTONIC, &ts_main_begin);
```

main 函数 `return 0;` 之前插入：
```c
clock_gettime(CLOCK_MONOTONIC, &ts_main_end);
{
    double main_s = (double)(ts_main_end.tv_sec - ts_main_begin.tv_sec)
        + (double)(ts_main_end.tv_nsec - ts_main_begin.tv_nsec) / 1e9;
    fprintf(stderr, "MAIN_ELAPSED_S=%.9f\n", main_s);
}
```

### 6. prio_runtime.h

FIFO 和各算法版本需要 `prio_runtime.h` 头文件。该文件提供 `l1_set_thread_prio_fifo(int prio)` 函数，用于在运行时设置线程的 SCHED_FIFO 实时调度策略和优先级。CFS 版本不需要此头文件。

## 输出位置

转换后的副本存放在：
```
粗略实验使用文件/中间文件/zhang{1,2,3}/pipeline/instrument/level2/effective_line_merge/
├── result/
│   ├── CFS/CFS.c
│   ├── FIFO/FIFO.c
│   ├── {algo}/{algo}.c
└── timing/
    ├── CFS/CFS.c
    ├── FIFO/FIFO.c
    └── {algo}/{algo}.c
```

共 3 个测试用例 × 8 个版本 × 2 类（result + timing）= 48 个 .c 文件。

## 注意事项

- 各算法的优先级数值来自旧文件中已有的 `l1_set_thread_prio_fifo(N)` 调用，不要修改
- CFS 版本不能包含任何 `prio_runtime.h` 或 `l1_set_thread_prio_fifo` 相关内容
- FIFO 版本只在 main 开头有一个统一优先级 99，子线程不设优先级
- timing 版本的测时变量声明 `ts_main_begin, ts_main_end` 放在 main 函数体最开头
