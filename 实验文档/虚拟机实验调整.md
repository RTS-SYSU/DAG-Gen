# 虚拟机实验调整（双场景版）

## 1. 任务目标（最终验收口径）

我们要在 **两核（c2）** 和 **四核（c4）** 两个场景下同时达成：

- `lpf（或 cpf）`、`heft`、`zhao2020` 三个算法整体优于 `CFS` 和 `fifo`。
- 尤其要求相对 `CFS` 有稳定优势，不是偶发单次领先。

评估口径固定为：

- `fifo` 按 `wcet_first/summary.json` 统计（即本实验中 `fifo = wcet_first`）。
- `lpf` 按 `cpf/summary.json` 统计（`lpf（cpf）` 统一口径）。

建议达标阈值（用于决策，不是硬数学证明）：

- 每个 DAG、每个场景下，三算法 `avg_s` 至少优于 `CFS` **5%**。
- 三算法中至少两个算法优于 `fifo`（按 `wcet_first` 口径）。
- `min_s` 与 `median_s` 方向一致（避免只靠异常值“看起来变好”）。

## 2. 可调整范围（硬约束）

- `dag5`、`dag6`：当前已稳定优于 `CFS`，作为成功基线，不优先动。
- `dag1`、`dag2`：可调 **结构 + 权重**。
- `dag3`、`dag4`：仅可调 **权重**，不可改结构与依赖关系。

---

## 3. 核心理论（为什么“关键路径算法”不一定天然赢）

`lpf/cpf`、`heft`、`zhao2020` 都偏向关键路径，但在 Linux + SCHED_FIFO + 分段插桩条件下，存在三个反直觉风险：

1. 高优先级线程会完全抢占低优先级线程  
2 核时尤为明显，可能把本应并行推进的分支“饿死”。

2. 关键触发线程被抢占会导致全局延迟  
如果 `sem_post` / `join` 相关段优先级被压低，后续整个 DAG 启动时间推迟。

3. 分段优先级跳变  
同一线程在不同 MU/SEG 段可能拿到不同优先级，导致“前半段快、后半段被反超”。

结论：  
我们要设计的是“**算法选对会显著收益，选错会显著受罚**”的 DAG，而不是单纯把总工作量加大。

---

## 4. 双场景（c2/c4）同时达标的设计准则

### 4.1 关键路径形态

- 关键路径必须“长且集中”，尽量减少跨线程来回切换。
- 关键路径后半段不能太轻，否则四核下很快被吞掉，优势消失。
- 关键路径要与至少一个 `join` 或最终收敛点强绑定，确保其完成时间直接决定总时长。

### 4.2 竞争窗口设计

- 两核：竞争窗口就绪任务数建议 `>= 3`。
- 四核：竞争窗口就绪任务数建议 `>= 5`，否则四核下竞争不足，CFS 也能“全都跑起来”。
- 至少设置 2 个竞争窗口（早期窗口 + 中后期窗口），避免单点设计对某一算法过拟合。

### 4.3 权重比例建议

- 关键段 / 非关键段 单段比值建议在 `1.8x ~ 3.0x`。
- 非关键分支前段不宜过重，避免抢占关键触发。
- 非关键分支后段可以中等偏重，用于制造“选错代价”。
- main 上触发段（post/create/join 前后）保持中轻量，避免被抢占导致触发延迟。

### 4.4 避免的反模式

- 反模式 A：大量等重长任务并行  
结果通常是 CFS 轮转收益最大。
- 反模式 B：关键线程后半段优先级骤降  
会被 filler 反超，`avg_s` 恶化。
- 反模式 C：关键工作过度依赖主线程后续触发  
主线程一旦被抢占，全局链条延后。

## 5. 各 DAG 调整策略（可直接执行）

### 5.1 dag1 / dag2（结构+权重）

目标：把当前“负载并发型”改为“关键决策型”。

建议动作：

- 保留一个明确关键 worker 链（2~3 段重任务），让其决定最终 join。
- 把非关键 worker 分成：
  - 早期轻段（快速进入可调度态）
  - 中后期中重段（用于制造错误调度代价）
- 在关键链完成前，确保至少有一个“可抢核但可延后”的干扰分支存在。
- 控制主线程段：只负责触发和收敛，不承担超重计算。

### 5.2 dag3 / dag4（仅权重）

目标：不改结构，只通过权重重塑“谁该先跑”。

建议动作：

- 先从 `timing.json + schedule.json` 标出：
  - 收敛点前必须完成的段（近关键段）
  - 可延后段（远关键段）
- 提升近关键段权重，降低远关键段前段权重。
- 如果算法仍输 CFS，优先增加“中后期关键段”的权重，而不是无差别整体放大。

## 7. 判定与诊断（每轮必须做）

### 7.1 快速判定

- 若三算法都输 CFS：说明竞争窗口设计失败或关键路径不够主导。
- 若 `min_s` 赢但 `avg_s` 输：说明存在饿死/抖动，优先修复中后段优先级跌落问题。
- 若 c2 赢而 c4 输：说明四核竞争不足，需要增加并行就绪数或第二竞争窗口。
- 若 c4 赢而 c2 输：说明两核下抢占过强，需要降低非关键高优先级段权重。
- 若只优于原始 FIFO 但不优于 `wcet_first`：按“未达标”处理（本实验口径以 `fifo=wcet_first` 为准）。

### 7.2 失败归因模板

- 触发延迟型：关键 `post/create` 被推迟。  
- 饿死型：关键后段长期拿不到核。  
- 过度并行型：CFS 轮转带来吞吐优势。  
- 过度串行型：结构本身限制调度自由度。

每轮只改一组假设，避免无法归因。
