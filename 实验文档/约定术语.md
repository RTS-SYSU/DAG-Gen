# ScratchDAG 约定术语

## 完整流程概念

ScratchDAG 的完整流程分为以下 **7 个阶段**：

### 1. **源码准备阶段**
- 输入：原始 C 源文件（如 `zhang1.c`）
- 输出：源文件本身
- 作用：准备待分析的 C 程序，通常包含关键链 + 填充任务的实验程序

### 2. **编译展开阶段**（expand 文件生成）
- 输入：C 源文件
- 输出：`.233r.expand` 文件（GCC RTL 中间表示）
- 命令：`gcc -fdump-rtl-expand <源文件>`
- 作用：生成 GCC 编译器的内部 RTL 表示，用于后续代码分析

### 3. **DAG 生成阶段**（生成dag图）
- 输入：expand 文件 + 源文件
- 输出：初始 DAG 图（`dag_seg.dot` + `dag_seg.png`）
- 作用：基于代码结构分析，生成任务依赖图的初始版本

### 4. **Collect 阶段**（收集基础信息）
- 输入：源文件
- 输出：`block_info.json`
- 命令：`pipeline collect --source <源文件>`
- 作用：分析源代码结构，建立基础元数据

### 5. **Blocks 阶段**（代码分块 + DAG 优化）
- 输入：block_info + 源文件
- 输出：`segments.json`、`dag_seg.json`、`dag_seg.dot/png`
- 命令：`pipeline blocks --level level2 --rule effective_line_merge`
- 作用：按规则分块代码段，生成优化后的 DAG 结构

### 6. **Timing 阶段**（执行时间测量）
- 输入：blocks 输出的代码段
- 输出：`timing.json`
- 命令：`pipeline timing --level level2 --rule effective_line_merge`
- 作用：测量每个代码段的实际执行时间（avg_ns）

### 7. **Schedule 阶段**（调度算法生成优先级）
- 输入：timing 结果 + DAG
- 输出：每个算法的 `schedule.json`
- 命令：`pipeline schedule --level level2 --rule effective_line_merge --algo cpf`
- 支持算法：cpf、heft、lpf、t_level、wcet_first、zhao2020
- 作用：使用调度算法为每个段分配优先级

### 8. **Instrument 阶段**（代码插桩 + 可视化 + 测时版本）
- 输入：schedule + 源代码
- 输出：
  - `source_original.c` + `source_instrumented.c`
  - `测时/` 目录（**每个算法都会同步生成**）
  - `instrument_meta.json`（包含 `timing_versions` 字段）
  - validation 可视化：`dag_seg_annotated.dot/png` + `dag_seg_annotated_value.dot/png`
- 命令：`pipeline instrument --level level2 --rule effective_line_merge --algo cpf`
- 作用：代码插桩、**同步生成测时对比版本**，并生成包含优先级信息的可视化图

**测时版本说明**（每个算法的 instrument 阶段都会生成）：
- `测时/baseline_FIFO.c`: baseline + FIFO调度（优先级99）+ 测时代码
- `测时/baseline_CFS.c`: baseline + CFS默认调度 + 测时代码
- `测时/prio.c`: prio版本（动态优先级）+ 测时代码
- 每个版本都包含 `MAIN_ELAPSED_S` 测时代码，可通过 `compile_and_run.sh` 统一测试

**集成方式**：在 `pipeline/instrument.py` 的 `run_instrument()` 函数中调用 `create_timing_versions()`，实现**所有算法同步生成**

## 关键术语

### 文件类型
- **`.c`**：C 源文件
- **`.233r.expand`**：GCC RTL 展开文件
- **`.dot`**：GraphViz DOT 格式图文件
- **`.png`**：渲染后的图文件
- **`.json`**：配置和结果文件

### 目录结构
- **`源文件/`**：原始实验程序
- **`配置文件/`**：编译和调试配置
- **`中间结果/`**：pipeline 处理结果
  - `pipeline/blocks/`：分块结果
  - `pipeline/timing/`：时间测量结果
  - `pipeline/schedule/`：调度结果
  - `pipeline/instrument/`：插桩结果
  - `pipeline/validation/`：可视化结果

### 算法名称
- **cpf**：Critical Path First
- **heft**：Heterogeneous Earliest Finish Time
- **lpf**：Longest Processing Time First
- **t_level**：Top Level
- **wcet_first**：Worst Case Execution Time First
- **zhao2020**：Zhao 2020 算法

### 关键概念
- **DAG**：有向无环图，表示任务依赖关系
- **RTL**：Register Transfer Language，GCC 的中间表示
- **插桩**：Instrumentation，在代码中插入测量/控制代码
- **优先级调度**：使用 SCHED_FIFO + 不同优先级进行实时调度

### CPU 核心速率（实验环境）

**测量时间**：2026-04-01（5次测量取平均）

**各核心速率（单位：MHz）：**

| 核心 | 5次测量平均 | 最大频率 | 备注 |
|------|-------------|----------|------|
| CPU0 | 609        | 1800    | 小核 |
| CPU1 | 446        | 1800    | 小核 |
| CPU2 | 566        | 1800    | 小核 |
| CPU3 | 528        | 1800    | 小核 |
| CPU4 | 408        | 2352    | 大核 |
| CPU5 | 408        | 2352    | 大核 |
| CPU6 | 408        | 2352    | 大核 |
| CPU7 | 489        | 2352    | 大核 |

**说明**：
- 小核（CPU 0-3）：最大可达 1.8GHz
- 大核（CPU 4-7）：最大可达 2.352GHz（推荐用于高性能实验）
- 实际运行时频率会动态调整（受负载和温控影响）

**实验建议**：
- 实验任务建议绑定到**大核（4-7）**以获得更高性能
- 系统后台任务可限制在小核（0-3），减少实验干扰
- 使用 `taskset -c 6,7` 可将程序绑定到核心 6 和 7
