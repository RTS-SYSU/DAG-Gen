## 4. RT 带宽配额（关键！影响实验结果）

### 4.1 全局 RT 节流

```
/proc/sys/kernel/sched_rt_runtime_us = 950000
/proc/sys/kernel/sched_rt_period_us  = 1000000
```

含义：每 1 秒周期内，全系统所有 SCHED_FIFO/RR 线程合计最多占 **950ms** CPU 时间，剩余 **50ms** 强制留给 CFS。

### 4.2 cgroup 层 RT 配额（`CONFIG_RT_GROUP_SCHED=y`）

| cgroup 路径 | `cpu.rt_runtime_us` | `cpu.rt_period_us` | 含义 |
|-------------|---------------------|--------------------|------|
| `/sys/fs/cgroup/cpu/`（顶层） | **950000** | 1000000 | 全局上限 |
| `/sys/fs/cgroup/cpu/user.slice/` | **900000** | 1000000 | 用户会话 RT 预算 |
| `/sys/fs/cgroup/cpu/system.slice/` | **0** | 1000000 | 系统服务无 RT 预算 |

### 4.3 当前进程所在 cgroup

```
cpu,cpuacct:/user.slice
```

### 4.4 RT 配额对实验的影响

**这是导致「CFS 在板子上总是最好」的主要原因。**

- 你的实验程序运行在 `user.slice` 下，RT 预算为 **900000 / 1000000 = 90%**
- 当多个 SCHED_FIFO 线程同时忙等时（例如 4 blocker + launcher + gate + tail），它们共享这 900ms 配额
- 配额耗尽后，**内核会节流所有 RT 线程**（暂停），把 CPU 让给 CFS 线程
- CFS 版本不受此限制，100% 时间都可用
- 因此 **FIFO/算法版本被周期性打断，CFS 版本反而更快**

### 4.5 永久化服务

```
# /etc/systemd/system/rt-cgroup-user-slice.service
# 状态：active（开机自动写入 900000）
ExecStart=/bin/sh -c 'echo 900000 > /sys/fs/cgroup/cpu/user.slice/cpu.rt_runtime_us'
```

此服务在之前的会话中创建，每次开机自动将 `user.slice` 的 RT 配额设为 900000。
