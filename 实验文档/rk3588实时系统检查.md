## 4. RT 带宽配额（关键！影响实验结果）

### 4.1 全局 RT 节流

```
/proc/sys/kernel/sched_rt_runtime_us = 950000
/proc/sys/kernel/sched_rt_period_us  = 1000000
```

含义：每 1 秒周期内，全系统所有 SCHED_FIFO/RR 线程合计最多占 **950ms** CPU 时间，剩余 **50ms** 强制留给 CFS。

### 4.2 cgroup 层 RT 配额（`CONFIG_RT_GROUP_SCHED=y`）

| cgroup 路径 | `cpu.rt_runtime_us` | `cpu.rt_period_us` | 含义 |
|-------------|---------------------|--------------------|------|
| `/sys/fs/cgroup/cpu/`（顶层） | **950000** | 1000000 | 全局上限 |
| `/sys/fs/cgroup/cpu/user.slice/` | **950000** | 1000000 | 与顶层一致，用户会话 RT 预算（已取消原先额外的 900000 限流） |
| `/sys/fs/cgroup/cpu/system.slice/` | **0** | 1000000 | 系统服务无 RT 预算 |

### 4.3 当前进程所在 cgroup

```
cpu,cpuacct:/user.slice
```

### 4.4 RT 配额对实验的影响

**原先 `user.slice = 900000` 时，这是导致「CFS 在板子上总是最好」的主要原因之一。**

- 程序在 `user.slice` 下，若 RT 预算为 **900000 / 1000000**，则比顶层 **950000** 再多扣一层 **10%**，FIFO 线程更容易被 cgroup 节流，CFS 不受影响。
- **现已改为 950000**，与顶层 `cpu` cgroup 一致，**不再比虚拟机多这一层 10% 限流**（虚拟机无 `RT_GROUP_SCHED`，无此文件；板子上仍受全局 950000、即约 5% 的 RT 节流）。

**说明：** 对 `user.slice/cpu.rt_runtime_us` 写入 **`-1`** 在本机内核上会报 **I/O error**，故采用 **950000** 作为合法最大值（不得超过父 cgroup）。

### 4.5 永久化服务

```
# /etc/systemd/system/rt-cgroup-user-slice.service
# 状态：active（开机自动写入 950000）
ExecStart=... echo 950000 > /sys/fs/cgroup/cpu/user.slice/cpu.rt_runtime_us
```

开机自动将 `user.slice` 的 RT 配额设为 **950000**，与顶层对齐。

## 6. 总结 & 对实验的影响

### 本机不是实时内核

- 抢占模型为 **`PREEMPT_VOLUNTARY`**（自愿抢占），非 `PREEMPT_RT`
- 没有 `/sys/kernel/realtime` 文件
- uname 中没有 `PREEMPT_RT` 或 `-rt` 字样

### 影响实验结果的关键参数

| 参数 | 当前值 | 对实验的影响 |
|------|--------|-------------|
| `CONFIG_RT_GROUP_SCHED` | **y** | cgroup 层会限制 RT 线程的 CPU 时间 |
| `user.slice/cpu.rt_runtime_us` | **950000** | 与顶层一致；仅受全局 RT 约 **5%** 节流（不再有 user.slice 额外 10%） |
| `sched_rt_runtime_us`（全局） | **950000** | 全局每秒最多 950ms 给 RT，**5% 被节流** |
| `CONFIG_HZ` | **300** | 时钟中断 300Hz（约 3.3ms 粒度），中等精度 |
| CPU governor | **interactive** | 动态调频，可能引入频率波动 |

### 与虚拟机环境的可能差异

| 项目 | rk3588（本机） | 虚拟机（待确认） |
|------|---------------|-----------------|
| 内核抢占模型 | `PREEMPT_VOLUNTARY` | 可能是 `PREEMPT` 或 `PREEMPT_RT` |
| `RT_GROUP_SCHED` | **y**（有 cgroup 限制） | 可能是 **n**（无限制） |
| `user.slice` RT 配额 | **950000**（与全局一致） | 无此文件 |
| 全局 `sched_rt_runtime_us` | 950000（95%） | 可能是 **-1**（不限制） |

### 若要让板子上 FIFO/算法比 CFS 更快

可调整配额（实验时临时执行，实验后按需恢复）：

```bash
# 与顶层对齐（当前默认，推荐）
echo 950000 | sudo tee /sys/fs/cgroup/cpu/user.slice/cpu.rt_runtime_us

# 取消全局 RT 节流（更激进；本机 user.slice 写 -1 可能 I/O error）
echo -1 | sudo tee /proc/sys/kernel/sched_rt_runtime_us

# 恢复全局默认
echo 950000 | sudo tee /proc/sys/kernel/sched_rt_runtime_us
```

⚠️ **警告**：取消 RT 节流后，若 SCHED_FIFO 程序有 bug（死循环 + 最高优先级），可能导致系统无法操作，需物理重启。
