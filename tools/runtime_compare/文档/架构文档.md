## 核心模块说明

### 1. Task（任务）

`core/task.py` 定义了 `Task` 数据类，包含：
- 任务基本信息（baseline_c, prio_c, work_scale, repeats 等）
- 任务状态（status, phase, progress）
- CPU 分配（cpu_set, cpu_list）
- 输出目录（out_dir）

### 2. CpuPool（CPU 池）

`core/cpu_pool.py` 管理 CPU 核心的分配和释放：
- `try_acquire_group(k, preferred)`: 尝试获取 k 个 CPU 核心
- `release_group(group)`: 释放 CPU 核心组
- `free_count()`: 获取空闲核心数量

### 3. TaskRunner（任务执行器）

`core/task_runner.py` 是任务执行的核心：
- 从队列获取任务
- 分配 CPU 核心
- 编译 C 程序
- 运行并收集结果
- 生成报告文件

### 4. 配置管理

`utils/config_manager.py` 提供：
- `save_config()`: 保存任务配置到 JSON（支持追加/覆盖模式）
- `load_config()`: 从 JSON 加载配置
- `validate_config()`: 验证配置文件格式
- `tasks_from_config()`: 从配置创建 Task 对象

配置文件存储位置：`tools/runtime_compare/配置文件/`

### 5. Web UI 模块

`ui/web/api.py` 提供 RESTful API：
- 任务管理：添加、列表、取消、查看日志
- 配置文件管理：列表、导出、导入、下载、删除
- 系统信息：CPU 状态、任务统计

`ui/web/templates/index.html` 提供：
- 系统信息显示
- 配置文件管理界面
- 任务添加表单
- 任务列表和详情
- 实时状态更新（轮询）

## 数据流

```
用户输入（GUI/Web/CLI）
    ↓
创建 Task 对象
    ↓
加入任务队列（Queue[Task]）
    ↓
TaskRunner 线程池获取任务
    ↓
从 CpuPool 分配 CPU 核心
    ↓
执行任务（编译 → 运行 → 收集结果）
    ↓
生成结果文件（summary.json, runs.csv, run.log, run_results.txt）
    ↓
更新任务状态
```

## 模式说明

### CLI 模式

- 适合离线环境和自动化脚本
- 通过命令行参数控制
- 支持从配置文件批量加载任务
- 不显示实时进度，只记录日志

### Web 模式

- 适合远程访问（如 RK3588 板子）
- 通过浏览器访问
- 支持实时查看任务状态（每 2 秒自动刷新）
- 自动和手动导出配置文件
- 配置文件导入/导出管理
- 任务详情查看和日志查看
- 进度条显示和任务筛选

### GUI 模式

- 适合本地桌面环境
- 使用 tkinter
- 支持拖拽和可视化操作
- 自动导出配置文件

## CPU 隔离机制

1. **工具层面**：使用 `os.sched_setaffinity()` 绑定进程到指定 CPU
2. **程序层面**：重写源码中的 `sched_setaffinity` 调用，将写死的 CPU_SET 替换为分配的核心
3. **池管理**：CpuPool 确保不同任务使用不重叠的 CPU 核心集合

## 结果格式

### summary.json

包含完整的统计信息和元数据：
- 任务信息（work_scale, repeats, cpu_set）
- baseline/prio 的统计（mean, min, max, median）
- 每次运行的详细信息
- 改进比例（improvement_ratio）

### runs.csv

每次运行的耗时表，便于数据分析：
```csv
program,iter,time_s,wall_s,parsed_from_stdout,cpu_set
baseline,0,1.234567890,1.234567890,1,"4,5,6,7"
prio,0,1.123456789,1.123456789,1,"4,5,6,7"
```

### run_results.txt

三段式文本报告（与 run.sh 格式一致）：
1. 配对表：每次 run 的 baseline/prio 耗时 + delta
2. 统计表：baseline 和 prio 的统计信息
3. 原始日志：每次运行的完整输出
